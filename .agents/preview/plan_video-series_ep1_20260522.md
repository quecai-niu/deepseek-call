# 视频系列第 1 集提案：UserPromptSubmit Hook

> 时间：2026/05/22
> 主题：用 Hook 注入规则，逼迫主 Agent 强制使用子代理

---

## 1. 问题：大代理什么都干，反而干不好

- 一个代理既读代码、又写代码、又检查代码 → 上下文爆炸、质量下降
- 实际观察：单代理改完代码"觉得对了"，其实根本没改对

## 2. 解法：UserPromptSubmit + remind-rules.ps1

- **Hook 触发点**：每次用户发送 prompt 时同步注入
- **注入内容**（展示具体规则）：
  - ⛔ 禁止主对话中直接编码/搜索/检查
  - ✅ 必须启动子代理（Agent 工具）执行
  - ✅ 主代理职责：拆任务 + 汇总结果
  - ✅ 改完代码再启独立审核子代理检查
- **技术关键**：`sync` 模式（非 async），10s timeout，用 `additionalContext` 注入系统提示词

## 3. 效果演示：Before / After

- **改造前**：主代理直接写代码，改完自认为"好了"
- **改造后**：主代理拆任务 → 子代理 A 写代码 → 子代理 B 审核 → 主代理汇总
- 代码质量：审核环节必须读代码全文，不会只靠 diff 判断

## 4. 这种模式背后的思想

- **主代理 = 管理者**，子代理 = 执行者
- 上下文隔离：每个子代理只看到自己的任务，不会污染主代理
- 审核链防止"改完就说好了"的认知偏差

## 5. 局限和代价

- 简单任务也会绕一次子代理，增加 token 消耗
- 需要写清晰的子代理提示词模板
- 不是所有场景都适合（纯对话、简单问答）

---

## 关联配置

- Hook 脚本：`hooks/remind-rules.ps1`
- Hook 模式：`sync`，注入优先级高于正常系统提示词
- 全局规则源：`CLAUDE.md` → 子代理使用规范章节
