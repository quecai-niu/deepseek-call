# DeepSeek 语音聊天应用 — 技术方案

## 一、整体架构

```
┌─────────────────────────────────────────────────────────┐
│                    单 HTML 文件                          │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌─────────┐ │
│  │ UI 层     │  │ 状态机   │  │ 语音管道 │  │ API 层  │ │
│  │ (DOM/CSS) │◀▶│ (State   │◀▶│ (STT/TTS)│  │ (fetch  │ │
│  │           │  │ Machine) │  │          │  │  + SSE) │ │
│  └──────────┘  └──────────┘  └──────────┘  └─────────┘ │
│                      │                                   │
│                 localStorage                             │
│              (API Key, 设置)                              │
└─────────────────────────────────────────────────────────┘
```

- **纯前端单文件**：一个 HTML 文件包含所有 CSS + JS，零依赖，零构建
- **无框架**：原生 DOM 操作，保持轻量
- **部署**：丢到任意静态托管即可

## 二、状态机设计（通话核心）

```
                    ┌─────────────┐
                    │   IDLE      │  初始/挂断状态
                    └──┬──────┬───┘
            拨号/接听  │      │  挂断
                    ┌──▼──┐   │
              ┌────►│LISTEN│◄──┘  持续监听用户语音
              │     └──┬───┘
              │   检测到语音
              │     ┌──▼───────┐
              │     │ USER_TALK│   用户正在说话
              │     └──┬───────┘
              │   识别完成，自动发送
              │     ┌──▼──────────┐
              │     │ AI_THINKING │   API 请求中（流式接收）
              │     └──┬──────────┘
              │   TTS 开始朗读
              │     ┌──▼──────────┐
              └─────│ AI_SPEAKING │  AI 正在朗读
      用户说完/句子结束    └──┬──────────┘
                     全部读完 ──► LISTEN（循环）
```

**状态流转规则**：
- IDLE → LISTEN：用户点击"开始通话"
- LISTEN → USER_TALK：SpeechRecognition 检测到语音
- USER_TALK → AI_THINKING：识别完成，发送消息
- AI_THINKING → AI_SPEAKING：收到第一个完整句子，开始朗读
- AI_SPEAKING → LISTEN：全部朗读完毕，继续监听
- **任意状态 → IDLE**：用户点击挂断
- **AI_SPEAKING/AI_THINKING → USER_TALK**：检测到用户打断

## 三、语音管道

### 3.1 语音输入（STT）

```
SpeechRecognition (continuous: true, interimResults: true, lang: zh-CN)
    │
    ├── onresult: 收集语音识别结果
    │   ├── interim（中间结果）→ 实时显示，不发送
    │   └── final（最终结果）  → 自动发送
    │
    └── onend: 识别停止 → 如果不是手动停止，自动重启继续监听
```

**关键处理**：
- `continuous: true` 保持持续监听，但浏览器可能在一段静默后自动停止
- `onend` 中判断：如果是意外停止（非手动挂断），自动 restart
- 识别语言设为 `zh-CN`（中文）
- 防抖：连续 final 结果在短时间内的去重处理

### 3.2 语音朗读（TTS）

```
SSE 流式文本
    │
    ├── 累积字符到缓冲区
    ├── 检测句子边界（。！？\n）
    ├── 切出完整句子 → 放入朗读队列
    └── SpeechSynthesis 逐句朗读
            │
            ├── onstart: 状态切到 AI_SPEAKING
            ├── onend: 检查队列，继续读或切回 LISTEN
            └── onerror: 降级（可能无中文语音，静默处理）
```

**句子切分逻辑**：
- 以 `。！？\n` 为分隔符
- 如果流式输出中 500ms 没有新字符，也把当前缓冲区作为一句
- 队列用数组管理，逐句出队朗读

## 四、API 层

### 4.1 请求格式

```javascript
POST https://api.deepseek.com/chat/completions
Headers: { Authorization: "Bearer ${apiKey}" }
Body: {
  model: "deepseek-chat",  // 或 deepseek-reasoner
  messages: [...],
  stream: true,
  // deepseek-reasoner 时附加:
  thinking: { type: "enabled", effort: "medium" }
}
```

### 4.2 SSE 解析

```javascript
fetch(url, { signal: abortController.signal })
  → response.body.getReader()
  → 逐行读取，解析 "data: {...}" 行
  → 提取 delta.content → 送入显示 + TTS 管道
  → 如果包含 reasoning_content → 显示思考过程
```

### 4.3 打断机制

```javascript
function interrupt() {
  abortController.abort();        // 取消 HTTP 请求
  speechSynthesis.cancel();      // 停止朗读
  ttsQueue.length = 0;           // 清空朗读队列
  transitionTo(USER_TALK);       // 切到用户说话状态
}
```

## 六、模块划分

| 模块 | 职责 | 关键接口 |
|------|------|----------|
| `StateMachine` | 管理通话状态，控制状态流转 | `transition(state)`, `onEnter(state, fn)` |
| `VoiceInput` | SpeechRecognition 封装 | `start()`, `stop()`, `onResult(cb)`, `onSpeechStart(cb)` |
| `VoiceOutput` | SpeechSynthesis + 句子队列 | `enqueue(text)`, `cancel()`, `onDone(cb)` |
| `DeepSeekAPI` | API 调用 + SSE 解析 | `sendStream(messages, onToken, onDone, signal)` |
| `SettingsStore` | localStorage 读写 | `get(key)`, `set(key, val)` |
| `ChatUI` | DOM 渲染，消息列表 | `addMessage(role, text)`, `updateLast(text)` |

| 功能 | Chrome Android | Safari iOS | Chrome Desktop |
|------|:---:|:---:|:---:|
| SpeechRecognition | ✅ | ⚠️ 部分支持 | ✅ |
| SpeechSynthesis | ✅ | ✅ | ✅ |

## 八、分阶段开发与测试

### 阶段一：文字聊天（基础能力验证）

**目标**：先保证文本输入 → 流式输出这条链路完全跑通。

```
用户打字 → 按发送 → SSE 流式显示 → 对话历史正确累积
```

**包含功能**：
- 聊天消息 UI（用户消息右对齐、AI 消息左对齐 + 流式逐字出现）
- DeepSeek API 调用 + SSE 流式解析
- API Key 设置面板（localStorage 存取）
- 主界面模型切换（deepseek-chat / deepseek-reasoner）
- 设置面板中 Reasoning Effort 滑块
- AI 思考过程（reasoning_content）展示（可折叠）
- 对话历史管理（重置/清空）

### 阶段二：语音功能（通话体验）

**目标**：在文字通道验证通过的基础上，叠加语音输入输出。

**包含功能**：
- 持续语音输入（SpeechRecognition + 自动发送）
- AI 回复 TTS 朗读（逐句流式朗读）
- 打断机制（P1）
- 语音不可用时的降级提示

**阶段二测试清单**：

| # | 测试项 | 预期结果 |
|---|--------|----------|
| 1 | 点击开始通话，麦克风授权 | 弹出权限请求，同意后进入监听状态 |
| 2 | 说话"你好"，自动识别并发送 | 文字出现在用户消息区，AI 开始回复 |
| 3 | AI 回复过程中 TTS 朗读 | 逐句朗读，语音自然 |
| 4 | 完整一轮通话后自动回到监听 | 继续等待下一轮语音输入 |

**阶段二就绪标志**：P0 语音项 1-4、7-9 通过；P1 打断项 5-6 尽力通过。
