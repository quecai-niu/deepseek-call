# DeepSeek 语音聊天应用 — 需求清单

## 核心理念

做一个**像打电话一样的** DeepSeek 聊天应用：打开网页 → 开始对话 → 你说、AI 听 → AI 说、你听 → 就像自然通话一样来回。

---

## 一、必须实现（P0）

### 1. 手机浏览器可用的 Web 应用
- 纯前端单页应用，移动端优先的响应式布局
- 不需要后端服务器，静态文件部署即可（GitHub Pages / Vercel）
- HTTPS 安全上下文（语音 API 需要，localhost 除外）

### 2. DeepSeek API 集成（流式输出）
- 直接从前端调用 DeepSeek API（`https://api.deepseek.com`）
- SSE 流式输出，边说边显示，不等完整回复
- 支持 `deepseek-chat`（V3）和 `deepseek-reasoner`（R1）模型切换
- **模型切换放在主界面**，方便快速切换（决策 D）

### 3. API Key 管理
- 用户填入自己的 DeepSeek API Key
- 存储在 localStorage，下次打开自动读取
- 提供设置入口可随时修改

### 4. Reasoning Effort 等级调节
- 支持 DeepSeek thinking mode 的四个等级：low / medium / high / max
- 调节方式：滑块或下拉选择器，放在设置面板中

### 5. 持续语音输入（"像打电话一样"）
- 打开麦克风后**持续监听**，不需要反复点击按钮
- 检测到用户说话 → 自动转为文字 → **直接自动发送**，无需手动确认（决策 B）
- 使用浏览器 Web Speech API（`SpeechRecognition`），中文识别
- 不说话时保持静默等待，不说话时不发送

### 6. AI 回复语音朗读（TTS）
- AI 返回的内容通过浏览器语音合成朗读出来
- 使用 `SpeechSynthesis` API，中文语音
- **逐句流式朗读**：AI 每输出一个完整句子就立即朗读，不等全部回复完成（决策 A）
- 实现方式：SSE 流式文本按句号/换行切分，每形成一个完整句子就送入 TTS 队列

### 7. 模型切换（主界面）
- 主界面上提供模型快速切换入口（deepseek-chat / deepseek-reasoner）
- 切换后立即生效，下次对话使用新模型

---

## 二、希望实现（P1）

### 8. 打断机制
- AI 正在朗读/思考时，用户开口说话 → 自动打断 AI
- 优先处理用户输入，停止朗读、发送新消息
- 实现要点：
  - 朗读时检测到用户语音 → `speechSynthesis.cancel()` 停止朗读
  - 同时 `AbortController` 取消当前 API 请求
  - 界面状态同步切换

---

## 三、暂不做的

- **通话视觉状态**（话筒动画、波形、通话时长等）：增加开发量，先保持简洁界面（决策 C）

## 四、后续扩展（不在本次范围，但预留空间）

### 联网搜索能力 — 可行性评估

**可行。** 实现路径有两种：

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| A：前端直连搜索 API | 用户额外配置搜索 API Key（Tavily/Exa），前端判断是否需要搜索时调用搜索 API，结果注入到发给 DeepSeek 的请求中 | 架构简单，保持纯前端 | 需要用户有两把 Key；"判断是否需要搜索"逻辑在前端较粗糙 |
| B：DeepSeek function calling | DeepSeek 支持 tool use，让模型自己决定何时搜索，前端执行 tool 调用搜索 API 后把结果传回 | 模型自主判断更准确，标准的 agentic 模式 | 实现复杂，需要 tool call 循环，增加延迟 |

**推荐路径**：先做方案 A，验证需求强度。如果搜索频繁使用，再升级到方案 B。

**技术储备**：
- DeepSeek API 兼容 OpenAI function calling 格式，支持 `tools` 参数
- 搜索 API 可选 Tavily（AI 搜索专用，有免费额度）或 Exa
- 实现时只需在现有流程中插入"搜索 → 注入结果"环节，不影响核心通话体验
